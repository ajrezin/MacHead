# MacHead release guide

This skill defines the standard MacHead release process. The recommended path is the GitHub Actions release pipeline (`.github/workflows/release.yml`): pushing an annotated `v*` tag triggers the full build, DMG packaging, R2 upload, appcast update, GitHub Release, and website deployment flow in the cloud. The local release script `Scripts/release-local.sh` was removed in 2026-10 and is no longer used.

## 0. Prerequisites

- Working tree is clean, repository is on `main`, and all pending release commits are pushed
- GitHub Actions is available (repository Settings → Actions is not disabled)
- Repository secrets are configured: `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` (write access to the `headlessmac-releases` R2 bucket)

## 1. Trigger a release

```bash
# Annotated tag; the tag message is the user-facing release note stored in appcast.json releaseNotes
git tag -a v0.1.24 -m "1. Added first-run telemetry notice; 2. Fixed several issues"
git push origin main --tags
```

When the release note is left blank, CI automatically uses the commit titles between the previous tag and the current tag (excluding chore(release) and merge commits).

## 2. CI execution (`release.yml`, 7 steps)

1. **Fetch third-party binaries**: nezha-agent / ServerStatus client / frpc / cloudflared; download both architectures and merge them with `lipo` into a universal binary; devtunnel is not bundled because of the Microsoft EULA
2. **Build**: `./build.sh <version> <build>`; the build number is automatically read from the current `appcast.json` value and incremented by 1
3. **DMG**: `hdiutil` packages the app as `MacHead-v<version>-macos-universal.dmg`
4. **Upload to R2**: `wrangler r2 object put headlessmac-releases/<DMG>`
5. **appcast**: update the five fields in `website/public/appcast.json` → bot commits `chore(release): update appcast.json for vX` and pushes to `main`
6. **GitHub Release**: automatically created with the bare tag name `vX` (without the "MacHead" prefix—product context is already implied by the repository, matching GitHub conventions), with the DMG attached as an asset and automatically generated technical commit logs
7. **Website deployment** (cascading): after the appcast commit is pushed to `main`, **Cloudflare Pages Git integration** automatically builds and deploys `headlessmac.com`, and OTA updates take effect immediately. Note: this commit is generated by `GITHUB_TOKEN` and, by GitHub design, does **not** trigger Actions in a cascade; the `deploy.yml` → `gh-pages` path does not apply to release commits (`gh-pages` is a legacy branch and does not serve the live domain)

## 3. Post-release verification

- Verify the Actions page shows both `release.yml` and the cascading `deploy.yml` as successful
- `https://headlessmac.com/appcast.json` has the updated `version` and `build` values
- `https://releases.headlessmac.com/MacHead-vX-macos-universal.dmg` is downloadable

## 4. Prohibited actions

- Never bypass the release process by editing the appcast version fields manually and pushing directly to `main` (this would trigger OTA updates for all users)
- Never commit the DMG directly into the repository
- Do not bundle or redistribute devtunnel (Microsoft proprietary EULA)

## 5. Development builds (non-release)

```bash
./build.sh --no-install   # Compile only; output is ./MacHead.app, without installing to /Applications or restarting
./build.sh                # Compile + install + restart (developer daily workflow)
```

Note: third-party binaries under `Resources/` are not stored in git; in a worktree environment, copy them from the main checkout before running `build.sh`.
